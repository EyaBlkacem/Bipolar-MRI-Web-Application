## 📊 BACKEND API ENDPOINTS NEEDED

Ensure these endpoints exist in your backend:

```
GET  /api/patients                    - Get all patients
GET  /api/patients/:id                - Get patient by ID
POST /api/patients                    - Create new patient
PUT  /api/patients/:id                - Update patient
DELETE /api/patients/:id              - Delete patient
GET  /api/patients/with-ia-models    - Get patients with IA model scores
GET  /api/patients/high-risk         - Get high-risk patients
GET  /api/patients/search?q=term     - Search patients
GET  /api/patients/statistics        - Get patient statistics

GET  /api/assessments                 - Get all assessments
GET  /api/assessments/:id             - Get assessment by ID
POST /api/assessments                 - Create assessment
PUT  /api/assessments/:id             - Update assessment
DELETE /api/assessments/:id           - Delete assessment
GET  /api/assessments/patient/:patientId - Get patient's assessments
POST /api/assessments/:id/generate-report - Generate report

GET  /api/notifications               - Get notifications
GET  /api/notifications/:userId       - Get user's notifications
POST /api/notifications               - Create notification
PUT  /api/notifications/:id/read      - Mark as read
DELETE /api/notifications/:id         - Delete notification
```

## 🔌 SOCKET.IO EVENTS TO EMIT

```javascript
// From backend to frontend
'appointment-booked'          - New appointment created
'appointment-status-changed'  - Appointment status updated
'patient-updated'             - Patient info updated
'patient-created'             - New patient created
'report-generated'            - Report created for patient
'assessment-completed'        - Assessment completed
'user-online'                 - User came online
'user-offline'                - User went offline
'consultation-started'        - Consultation started
'consultation-ended'          - Consultation ended

// From frontend to backend
'register'                    - Register user ID
'joinRoom'                    - Join notification room
'send-message'                - Send message
```

## 📱 RESPONSIVE DESIGN

All components should be responsive:
- Desktop: Full grid layouts
- Tablet: 2-column grids
- Mobile: 1-column stacked layouts

## ⚡ REAL-TIME UPDATES

All data updates instantly when:
- New patient is added
- Patient info is updated
- New appointment is booked
- Appointment status changes
- Report is generated
- Assessment is completed
- New message arrives
- User comes online/offline

## 🔐 SECURITY NOTES

- All API calls include Authorization header with token
- Data filtering happens on frontend (user can bypass)
- Backend should validate permissions on all endpoints
- Sensitive data should never be exposed in notifications
